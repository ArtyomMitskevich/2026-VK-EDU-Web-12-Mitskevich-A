# Точка сборки

Учебный сайт инженерных вопросов и ответов. В ДЗ3 страницы читают данные из PostgreSQL. Наполнять базу можно через админку и команду `fill_db`.

## Настройка окружения

При первом запуске скопируйте `.env.example` в `.env.local` и `.env.docker`. Укажите одинаковые `POSTGRES_DB`, `POSTGRES_USER` и `POSTGRES_PASSWORD` в обоих файлах. Замените заглушки пароля и ключа Django своими значениями.

| Файл | Хост базы | Порт |
| --- | --- | --- |
| `.env.local` для Python в PyCharm | `127.0.0.1` | `55432` |
| `.env.docker` для Django в Compose | `db` | `5432` |

Оба файла исключены из Git. Корневая команда запускается из папки с `manage.py`. Для запуска с Docker сначала откройте Docker Desktop.

## Django в PyCharm, PostgreSQL в Docker

Выберите интерпретатор проекта и выполните команды в терминале. Если у текущего терминала другой Python, выполните их через полный путь к выбранному интерпретатору.

```powershell
docker compose up -d --wait db
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Сайт открывается на [127.0.0.1:8000](http://127.0.0.1:8000/), админка — на [/admin/](http://127.0.0.1:8000/admin/). У PostgreSQL своя база. Если суперпользователь был создан в SQLite, создайте его снова в PostgreSQL. Команду `createsuperuser` можно пропустить, если учётная запись в PostgreSQL уже есть.

## Django и PostgreSQL в Docker Compose

Перед запуском освободите порт 8000, если там работает сервер PyCharm. Compose ожидает готовности базы, применяет миграции и запускает Django. Код подключается из рабочей папки, данные PostgreSQL и загруженные файлы лежат в отдельных томах.

```powershell
docker compose up --build
```

Во втором терминале можно создать администратора и наполнить базу.

```powershell
docker compose exec web python manage.py createsuperuser
docker compose exec web python manage.py fill_db 2
```

Для остановки используйте `docker compose down`. Именованные тома сохраняются при обычной остановке и пересоздании контейнеров.

## Наполнение базы и проверка

При запуске Django из PyCharm выполняйте `python manage.py fill_db 2`. Такой запуск создаст 2 пользователей с профилями, 2 тега, 20 вопросов, 200 ответов и 400 оценок. Повторный вызов добавляет новую порцию данных. У сгенерированных пользователей отключены пароли.

`python manage.py fill_db 10000` создаёт 10 000 пользователей с профилями, 10 000 тегов, 100 000 вопросов, 1 000 000 ответов и 2 000 000 оценок. Запись идёт пакетами через `bulk_create` в одной транзакции. Минимальный коэффициент — 2. При одном пользователе на 110 объектов можно оставить максимум 110 уникальных оценок, а формула ТЗ требует 200.

```powershell
python manage.py test
```

При `DJANGO_DEBUG=1` справа на локальном сайте доступна Django Debug Toolbar. Во вкладке SQL можно проверить запросы страницы.

При проверке ДЗ3 генератор с `ratio=10000` создал все записи по формулам в отдельной базе PostgreSQL. Главная и популярные вопросы выполняли по 5 запросов, страница тега и отдельный вопрос — по 6. На этой машине полный набор генерировался около 5 минут. Для повседневной разработки удобнее небольшой `ratio`.

## Что где лежит

| Путь | Назначение |
| --- | --- |
| `application/settings.py`, `application/urls.py` | Настройки, PostgreSQL, общие шаблоны, медиа и Debug Toolbar |
| `core/models.py`, `core/admin.py` | Профиль и его редактирование внутри карточки встроенного пользователя Django |
| `questions/models.py` | Вопросы, ответы, теги, оценки и менеджеры выборок |
| `questions/admin.py` | Русскоязычные списки и формы. Ответы доступны внутри карточки вопроса |
| `core/migrations/`, `questions/migrations/` | Схема PostgreSQL и ограничения на оценки |
| `questions/views.py`, `questions/pagination.py` | Страницы новых, популярных, отдельных вопросов и тегов. Общая пагинация с возвратом на первую страницу при неверном номере |
| `questions/context_processors.py` | Популярные теги и участники для боковой колонки |
| `questions/management/commands/fill_db.py` | Генератор данных на Faker |
| `templates/base.html`, `questions/static/questions/` | Общий шаблон в корне и статика приложения с префиксом `questions/` |
| `questions/tests.py` | Проверка маршрутов, ограничений, объёмов генерации и числа запросов |
| `public/` | Исходная статическая версия ДЗ1 |

Ответ, добавленный из карточки вопроса, записывается от имени текущего администратора. Для выбора другого автора откройте отдельную форму ответа.

## ДЗ4. Авторизация и формы

При обновлении с ДЗ3 установите зависимости из requirements.txt (добавлен Pillow) и выполните `python manage.py migrate`. Для контейнера используйте `docker compose up --build`.

Регистрация создаёт пользователя и профиль. После входа можно изменить ник, email и аватар, задать вопрос с тегами через запятую и ответить на вопрос. Отправка ответа открывает страницу с новым ответом. Кнопки голосования и выбора решения работают через fetch и CSRF. Выбрать решение может автор вопроса.

Формы аккаунта находятся в `core/forms.py`, формы публикации и голосования — в `questions/forms.py`, обработчики браузера — в `questions/static/questions/js/script.js`. Аватары сохраняются в media/avatars под случайными именами.

Чтобы запустить сайт через nginx, освободите порт 8000 и выполните `docker compose --profile proxy up --build`. Откройте [сайт на порту 8080](http://127.0.0.1:8080/). По пути `/media/` nginx отдаёт файлы из тома `media_data`, куда Django сохраняет аватары. Остальные запросы передаются Django.
