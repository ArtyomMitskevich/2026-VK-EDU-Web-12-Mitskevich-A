# Точка сборки — ДЗ2

Учебный Django-сайт инженерных вопросов и ответов. Данные — списки Python,
без моделей БД и обработки форм. Подход семинара: views, именованные URL,
extends/include, локальная статика и Paginator.

## Локальный запуск (Windows PowerShell, Python 3.12)

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

При существующем .venv повторно создавать его не нужно.
Открыть http://127.0.0.1:8000/ . Миграции нужны встроенным приложениям Django,
сами вопросы пока хранятся в questions/data.py.

## Docker Compose

Запустить Docker Desktop с Linux containers, затем из корня проекта:

```powershell
docker compose up --build
```

Открыть http://127.0.0.1:8000/ . Остановка: Ctrl+C, затем `docker compose down`.
Если локальный runserver уже использует порт 8000, сначала остановить его.
Миграции встроенных приложений: `docker compose run --rm web python manage.py migrate`.
Код подключён через volume, media хранится в именованном volume media_data.

## Настройки

`.env.example` содержит имена переменных и безопасные примеры.
Compose автоматически читает `.env` из корня, если он создан по образцу.
При локальном запуске настройки берутся из переменных окружения PowerShell;
без них действуют значения для разработки. Django сам `.env` не читает.

## Маршруты

- `/` — 15 вопросов, по 4 на странице (сохранена выбранная настройка).
- `/hot/` — сортировка по рейтингу, пагинация.
- `/tag/electronics/` — фильтр по тегу; `/tag/cad/` — пример пустого списка.
- `/question/35/` — отдельный вопрос с пагинацией ответов по 2.
- `/ask/` — создание вопроса (форма-заготовка).
- `/login/`, `/signup/`, `/profile/` — страницы пользователя.

Номер страницы: `?page=2`. Нечисловые, отрицательные и отсутствующие страницы
заменяются первой. Неизвестные вопросы и теги возвращают 404.

## Структура

- application/ — настройки и корневые маршруты.
- questions/ — обработчики, данные, paginate, шаблоны и исходная статика.
- core/ — страницы пользователя.
- public/ — сохранённая статическая вёрстка ДЗ1.
- static/ — результат collectstatic, исключён из Git.
- media/ — пользовательские файлы, исключены из Git.

Формы, лайки и отметка правильного ответа пока демонстрируют интерфейс.
Регистрация, вход, сохранение данных и поиск в ДЗ2 не реализованы.
Шапка проверяет user.is_authenticated; для реальной проверки можно после
миграций создать пользователя через `python manage.py createsuperuser`
и войти в `/admin/`. Пароли и .env не добавлять в Git.
